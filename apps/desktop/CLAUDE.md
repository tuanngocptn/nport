# apps/desktop

## Scope

Tauri v2 desktop app: a GUI for people who would rather not use a terminal, plus a traffic inspector that the native connector makes nearly free. Rust backend linking `crates/core` directly, React frontend in the system WebView.

**Not responsible for:** any tunnel logic. All of it lives in `crates/core`; this app is a view over `TunnelEvent`s plus a few commands.

**The approved design is `docs/mockup/NPort Desktop.dc.html`**, with the layout flattened to plain markup in `docs/mockup/handoff/desktop/index.html`. Read `docs/mockup/README.md` before building or changing anything visual. It is reference only: never imported, never hand-edited, excluded from every check.

**Build every element it draws.** A control whose data does not exist yet is rendered as designed and inert, with the reason on it — not deleted. Deleting it hides that the app is unfinished and quietly loses the design; the mockup is the authority on *what is there*, and `docs/mockup/README.md` rule 4 is the only exception, for where it contradicts an invariant. What a missing backend changes is the **value**: `—` where a number would be a false claim, and the element still drawn around it.

**Status: Phase 4 in progress.** The shell, Tunnels and New tunnel are built against the mockup and wired to `nport-core`; Inspector, History and Settings are reachable and state what they will hold. **Nothing has been seen in a running window** — there is no browser tier and CI cannot open one.

## Rules

1. **Dual workspace membership.** This directory belongs to the pnpm workspace as `apps/*` **and** `src-tauri` is a Cargo workspace member. Both `pnpm install` and `cargo` see it. This surprises people; it is intentional (ADR-0008).
2. **The frontend never talks to `api.nport.link` directly.** All network activity goes through `crates/core` via IPC, so there is exactly one implementation of the lifecycle and one place tokens live.
3. **`src/generated/bindings.ts` *will be* generated** by `tauri-specta` from the Rust command signatures, in Phase 4. Rust is the authority for this boundary (ADR-0009), so when it lands the flow is: change the command, then regenerate. **None of it exists yet** — `tauri-specta` is not a dependency, `apps/desktop` has no `codegen` script, and `pnpm codegen` therefore does not touch this app (`docs/ROADMAP.md`, defect 42). Until then the IPC shape is hand-typed in `src/ipc/`, which `src/ipc/health.ts` says on itself.
4. **Capabilities gate plugin and `core:` commands, not this app's own.** A command registered in `generate_handler!` is invocable without an entry — `health` has never had one and the round-trip works, and the generated ACL manifests in `src-tauri/gen/schemas/` contain no app command at all. What *does* need an entry is a plugin permission (`opener:default`) or a core one. This rule used to say every command needed an entry, which sends people adding a permission that does not exist and failing the build (`docs/ROADMAP.md`, defect 47).
5. **All state is local.** No telemetry, no analytics, and above all **no tunnel traffic ever leaves the machine** (ADR-0015). The inspector exists because we can see traffic; that is a reason to be careful, not a reason to send it anywhere.
6. **Never render a tunnel token or `ownerToken` in the UI**, including in the logs view. Redact at the `core` boundary so the frontend never receives them.
7. **Import `@nport/contract/subdomain`, not `@nport/contract`.** The root export pulls zod in for its request schemas, which cost 82 kB of a desktop bundle that only needed pure string rules. The subpath exists for this; check what a new contract import drags with it before adding one.
8. **Colours come from `packages/design-tokens`** — the same token file as the site (ADR-0010). Import it in `styles.css`; this app runs its own Tailwind v4 build over it. **Never a raw hex value in a component.**
9. **`src/components/ui/` is vendored shadcn/ui source.** Edit it freely to fit our tokens — that is the point of a copy-in library — but keep changes minimal and note them, because upgrades are manual re-copies. App-specific components go in `src/components/`, not here.
10. **No component library with a runtime theming layer** (MUI, Mantine, Chakra). They would have to be reconciled with our tokens rather than consuming them, and they cost styling work in the WebView (ADR-0021).
11. **The request table must be virtualized** via TanStack Virtual. `core::inspector` can hold thousands of exchanges and a plain `.map()` will visibly stall the app.
12. Long-running work belongs in Rust with events pushed to the WebView. Do not poll from the frontend.

## Common tasks

**Add a command** — `src-tauri/src/commands.rs` → register it in `generate_handler!` in `lib.rs` → call it through `src/ipc/`. No capability entry (rule 4); `pnpm codegen` joins this list when `tauri-specta` does.

**Add an event** — add the variant in `crates/core` (`TunnelEvent`), forward it in `src-tauri/src/events.rs` — a `UiEvent` arm and a line in `every_variant_this_build_knows_translates`, which is what catches the omission — then handle it in the relevant view. The CLI must also handle it or it renders as nothing — `TunnelEvent` is `#[non_exhaustive]`, so the wildcard arm swallows a variant the compiler never warned about. `crates/core/src/event.rs` carries an exhaustive match whose only job is to stop compiling when the enum grows; update it and `crates/cli`'s `renders_something_for_every_variant` in the same change.

**Add an inspector column** — the data comes from `core::inspector`. If the field is not captured there yet, add it to `core` first; the exchange record is the contract. Keep the row renderer cheap — it runs inside a virtualizer.

**Add a shadcn component** — `pnpm dlx shadcn@latest add <name>`, then check the generated file actually uses our tokens rather than shadcn's default CSS variables, and verify it renders on WebKitGTK before assuming it works everywhere.

**Change the tray menu** — `src-tauri/src/tray.rs`. Verify on all three platforms; tray behaviour differs more than anything else in Tauri.

## Gotchas

- **The inspector must be bounded.** `core::inspector` is a ring buffer behind an optional sink; the desktop app enables it, the CLI does not. An unbounded buffer will eat memory on a busy tunnel — and bodies must be truncated, not stored whole.
- **WebView differences are the main source of platform bugs** — WKWebView, WebView2, WebKitGTK — and **WebKitGTK is the oldest engine we ship against**, so check very recent CSS on Linux before relying on it. This is the class of bug that reaches you as a Linux user's screenshot rather than a failing test. **The glass question is settled — ADR-0050**: the window is opaque and paints `--np-page`, every translucent surface composites over it, and `backdrop-filter` adds only the blur. Transparency turns on per platform via `[data-glass="on"]`, in the same change that installs a vibrancy layer for it, and **Linux is expected to stay opaque** because no portable API can blur behind a window there. Do not reintroduce `transparent: true` as a global default: surfaces at 7% opacity over a user's wallpaper is what that produces.
- **`cargo` commands from the repo root include `src-tauri`.** A `cargo clippy` failure here can surprise you when you thought you were only touching `crates/`.
- **Enabling `core::inspector` changes `core`'s hot path.** Keep the sink cheap and non-blocking, or the GUI makes tunnels measurably slower than the CLI.
- **Signing and notarization are required**, not optional — an unsigned build triggers Gatekeeper and SmartScreen warnings and generates support load. `docs/RELEASE.md`.
- **Auto-update must be tested from the previous version**, not from a fresh install. A broken updater is the one bug users cannot work around.
- The app links `crates/core` **in-process**. A panic in `core` takes down the whole app, so `core` must return errors rather than panicking.
